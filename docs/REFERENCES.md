## Shader compiler attribution

Both consoles use custom AMD graphics hardware. AnyPS5’s fetch test supplies PlayStation AGC user-data registers and buffer descriptors to its compiler. Frosty packages native Xbox instructions inside Direct3D shader containers and supplies input layouts through D3D12.x. A shared instruction encoding tells us what to decode. We still need the Xbox call site and signature to determine which position or texture coordinate reaches a register. [Sony hardware specifications](https://blog.playstation.com/2020/11/09/ps5-the-ultimate-faq/) · [Xbox Series X specifications](https://news.xbox.com/en-us/2020/03/16/xbox-series-x-tech/) · [AnyPS5 fetch setup](https://github.com/boykopovar/AnyPS5/blob/932393e35c2e49fdef9789dec4ebad6bed0dd3e0/core/libs/prx/libSceAgcDriver/tests/execution/ScalarSwappcFetch.cpp#L45-L70) · [Frosty vertex fetch](SHADERS.md#vertex-fetch)

TuxBox reads DXBC signatures, pipeline validation data, and root signatures from the documented DirectX layouts. The XDAT, FSSM, and FSPX readers were developed against shader bytes from supplied titles. The RDNA decoder uses AMD’s published instruction encodings. Its generated opcode table includes AMD’s MIT-licensed data. [DirectX container format](https://llvm.org/docs/DirectX/DXContainer.html) · [AMD ISA tables](https://gpuopen.com/machine-readable-isa/) · [AMD data license](licenses/amd/isa-MIT.txt)

TuxBox independently emits HLSL for supported pixel exports, fragment discards and compute buffer initializers or empty dispatches. The default compiler also includes the TomBox-derived HLSL emitter and its resource-binding code, which Frosty still needs for most shaders. Building the compiler with `--no-default-features` omits that implementation. ScarlettX is a research reference. [Shader coverage and build commands](SHADERS.md#independent-translation) · [Compiler notice](../tools/shader-compiler/NOTICE) · [Apache license](licenses/tombox/Apache-2.0.txt)

## Source attribution for runtime patches

The graphics patches in `tools/reference/tombox-*.patch` target the `d3d12_xs` and `tuxbox-xshader` crates in brcly’s fork of drycheetah84/TomBox. Credit for the underlying runtime and translator belongs to the TomBox contributors. Both crate manifests declare `MIT OR Apache-2.0`. Source from those crates appearing in the patches is distributed here under the Apache License, Version 2.0. The unified diffs identify the changes made for TuxBox. [Original TomBox project](https://github.com/drycheetah84/TomBox) · [Fork history](https://github.com/brcly/TomBox/commits/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/) · [D3D12 manifest](https://github.com/brcly/TomBox/blob/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/crates/compat/d3d12_xs/Cargo.toml) · [Shader translator manifest](https://github.com/brcly/TomBox/blob/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/crates/tuxbox-xshader/Cargo.toml) · [Applicable Apache license text](licenses/tombox/Apache-2.0.txt)

The separate keyboard and mouse patch extends the C++ GameInput provider that brcly introduced in the fork. Its source history is independent of the two Rust crate manifests. [Original GameInput change](https://github.com/brcly/TomBox/commit/b0181be854e50d9745a731db9903d0410897435a)

The ScarlettX adapter connects the observed threading interface slot to ScarlettX’s existing task queue termination function. It applies to a separately supplied ScarlettX checkout and contains the adapter and its table-entry change. That upstream revision has no license file. [ScarlettX source revision](https://github.com/Freminet/ScarlettX/tree/3eb694821b51c862c52b1a98ac382ba40eb07f74) · [Adapter patch](../tools/reference/scarlettx-task-queue-terminate.patch)

The Lanes example and the synthetic probes are maintained in this project. Retail games, Xbox system libraries and SDK tools are supplied separately.
