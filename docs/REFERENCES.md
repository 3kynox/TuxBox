# Research sources

Record the source revision, observed guest build, hardware and experiment whenever a finding changes the runtime. Public desktop API documentation gives an expected desktop result. An Xbox export with the same spelling still needs a guest call-site or ABI check.

| Source | How it informs this project |
|---|---|
| [TomBox fork, ca6cf6a](https://github.com/brcly/TomBox/tree/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a) | Provides the reference runtime, D3D12.x call profiles by GDK edition, and shader translation used for the Frosty experiments. The tested fork also included working-tree changes after this commit. |
| [6Stars](https://github.com/Ahmet-Dedeler/6Stars/tree/a16d99bb180eb7cf86632bf99df3174ec8ef11f5) | Research the RAGE-specific asset and PSO layouts. Select a particular archive record, hash the input and compare a known output. Other engines may have different packaging. Its [source license](https://github.com/Ahmet-Dedeler/6Stars/blob/a16d99bb180eb7cf86632bf99df3174ec8ef11f5/LICENSE) has custom redistribution terms. |
| [ScarlettX](https://github.com/Freminet/ScarlettX/tree/bda18b4d3dab501dd0f372e5d1921f462c6bd457) | Compare published Windows HLE results and limitations for Concept Destruction. The reported delay in exposing CPU-written texture data suggests a regression test with two distinct uploads and submissions in one frame. |
| [Xodus](https://github.com/xodus-gaming/xodus/tree/49453a4a458f8d9d0e8c93de6319d60b4291fa59) and [its Gaming Runtime](https://github.com/xodus-gaming/xgameruntime) | Use PC GDK package and runtime behavior as a comparison for configuration, storage and user APIs. Verify console imports and GPU interfaces separately. The projects publish GPL and LGPL terms respectively. |
| [Microsoft Xbox GDK samples](https://github.com/microsoft/Xbox-GDK-Samples/blob/main/gdk-samples-list.md) and [repository notices](https://github.com/microsoft/Xbox-GDK-Samples/blob/main/NOTICE.md) | Select targeted behaviors from SimpleTriangle, GameInputInterfacing and AMD_FSR. Record the sample revision and whether the binary was built for PC or Scarlett. |
| [MicrosoftGame.config executable schema](https://learn.microsoft.com/en-us/gaming/gdk/docs/reference/system/microsoftgameconfig/elements/microsoftgameconfig-element-executable) and [PE/COFF](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) | Resolve declared executables and keep named, ordinal, ordinary and delay imports distinct. Compare [pefile](https://github.com/erocarrera/pefile) with LLVM on supplied files. |
| [Microsoft x64 ABI](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention), [DirectX specifications](https://microsoft.github.io/DirectX-Specs/) and [DXC](https://github.com/microsoft/DirectXShaderCompiler) | Match host argument passing, COM lifetime, barriers and root signatures. Compile host DXIL and retain its compiler version in shader-cache keys. |
| [AMD RDNA2 instruction set](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf) | Define expected wave, EXEC, VCC, memory and floating-point behavior. Differential tests on a real RDNA2 device can disambiguate shader inputs and instructions. |
| [Wine](https://gitlab.winehq.org/wine/wine), [Valve Proton](https://github.com/ValveSoftware/Proton) and [vkd3d-proton](https://github.com/HansKristian-Work/vkd3d-proton) | Let the host handle PE loading and Win32. On Linux, submit translated desktop D3D12 to the selected provider's graphics implementation. Valve Proton uses vkd3d-proton for D3D12. Record provider and driver separately. |
| [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom) and [UMU](https://github.com/Open-Wine-Components/umu-launcher) | Use an installed distribution through UMU outside Steam. Run Valve and GE in separate prefixes so a provider-specific fix is visible. |

## Source attribution for runtime patches

The graphics patches in `tools/reference/tombox-*.patch` target the `d3d12_xs` and `tuxbox-xshader` crates in brcly’s fork of drycheetah84/TomBox. Credit for the underlying runtime and translator belongs to the TomBox contributors. Both crate manifests declare `MIT OR Apache-2.0`. Source from those crates appearing in the patches is distributed here under the Apache License, Version 2.0. The unified diffs identify the changes made for TuxBox. [Original TomBox project](https://github.com/drycheetah84/TomBox) · [Fork history](https://github.com/brcly/TomBox/commits/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/) · [D3D12 manifest](https://github.com/brcly/TomBox/blob/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/crates/compat/d3d12_xs/Cargo.toml) · [Shader translator manifest](https://github.com/brcly/TomBox/blob/ca6cf6a6b44e36d3ca4420db55a660a7bc6d6d5a/crates/tuxbox-xshader/Cargo.toml) · [Applicable Apache license text](licenses/tombox/Apache-2.0.txt)

The separate keyboard and mouse patch extends the C++ GameInput provider that brcly introduced in the fork. Its source history is independent of the two Rust crate manifests. [Original GameInput change](https://github.com/brcly/TomBox/commit/b0181be854e50d9745a731db9903d0410897435a)

The ScarlettX adapter connects the observed threading interface slot to ScarlettX’s existing task queue termination function. It applies to a separately supplied ScarlettX checkout and contains the adapter and its table-entry change. That upstream revision has no license file. [ScarlettX source revision](https://github.com/Freminet/ScarlettX/tree/3eb694821b51c862c52b1a98ac382ba40eb07f74) · [Adapter patch](../tools/reference/scarlettx-task-queue-terminate.patch)

The Lanes example and the synthetic probes are maintained in this project. Retail games, Xbox system libraries and SDK tools are supplied separately.
